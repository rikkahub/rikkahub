# Agent 权限与工作区链路简化设计

## 目标

将 Agent 权限的最终决定权交给用户，并把当前分散在风险策略、工具开关和工作区详情中的配置收敛为助手级三档模式。同时缩短助手绑定工作区的操作路径，让用户无需在多个页面之间往返。

## 权限模型

权限模式保存在 `Assistant` 上，每个助手独立配置：

- `AUTO_REVIEW`：使用现有风险引擎。高风险、未知工具、副作用操作和工具自身声明的审批要求都会触发确认。
- `FULL_ACCESS`：用户明确授权后，工具调用不再触发审批。PLAN 只读限制、受控子 Agent 只读限制、缺少工作区和工具被禁用等结构性约束仍不可绕过。
- `CONFIRM_CRITICAL`：默认模式。普通工作区读写和代码编辑自动执行；Shell、未知工具、MCP 明确要求审批以及敏感设备操作仍由用户确认。

模式进入权限摘要值，运行期间切换模式会使冻结的工具配置失效，避免旧授权在新策略下继续运行。现有工作区逐工具覆盖继续兼容，但不再作为主要配置入口。

## 工作区交互

助手基础设置与聊天附件面板共用 `WorkspaceSelectSheet`。选择面板提供取消绑定、选择现有工作区、直接创建、进入单个工作区详情和管理全部工作区。新建成功后立即绑定到当前助手，不再要求用户返回后再次选择。

助手基础设置把“工作区”和“Agent 权限”放在相邻区域；聊天附件面板即使没有工作区也显示入口，因此首次使用可以直接完成创建与绑定。

## 验证

权限策略使用 JVM 单元测试覆盖三档模式和硬约束优先级；工具配置摘要测试覆盖模式变化；UI 通过 Kotlin 编译和现有测试验证参数链路与 Compose 结构。
